# 场景搜集图鉴系统 — 需求文档

## Problem Frame

当前引擎中，词汇习得只发生在 NPC 对话任务流程里——孩子被动接受目标词汇，缺少主动探索的动力。6-12 岁儿童的英语学习需要更高的「开口剂量」，而现有场景中孩子完成对话任务后缺少在场景里继续逗留、继续接触新词的理由。

解决方向：在每个场景中埋入可搜集的小物件（每个物件 = 一个英语单词），孩子自由探索时发现、搜集它们，搜集到的词汇进入图鉴（Compendium），可随时回看、听发音、看例句。核心目标不是做游戏，而是让「主动探索 → 接触新词 → 自然记忆」成为一个平行于对话任务的独立循环。

---

## Actors

- A1. **儿童学习者 (6-12 岁)**：在体素场景中自由走动，发现发光的搜集物并按 E 键搜集，搜集后在图鉴中查看、听发音、学例句。
- A2. **引擎（系统）**：管理搜集物的渲染、交互检测、搜集动画、持久化读写、图鉴 UI 渲染、TTS 发音和 LLM 例句生成。
- A3. **场景作者（人或 AI）**：通过声明式配置定义场景的 `targetVocabulary`，引擎自动将其转化为搜集物。可选地通过 `collectibles` 字段手动指定位置、SVG 或补充词汇。

---

## Key Flows

- F1. **发现并学习词汇（搜集）**
  - **Trigger:** 儿童在场景中自由走动，靠近一个未搜集的物件
  - **Actors:** A1, A2
  - **Steps:**
    1. 儿童进入物件的一定范围内（如 2 格），物件开始发光
    2. 物件旁边出现「E」交互提示（桌面端键盘 E / 可点击）
    3. 儿童按下 E 或点击——**学习时刻开始**：物件 SVG 图标放大浮现到屏幕中央，引擎立即通过 TTS 朗读单词发音
    4. 界面显示喇叭按钮（🔊），儿童可反复点击重听发音——想听多少次都可以
    5. 界面显示确认按钮（如「Got it! ✓」），儿童点击确认后——**搜集完成**：引擎播放庆祝动画（SVG 缩小淡出 + 喝彩/铃铛音效），持久化到数据库，物件从场景中消失
  - **Outcome:** 儿童先听到并学会单词发音，确认后该词汇进入图鉴，本次会话中不再出现该物件
  - **Covered by:** R1, R2, R3, R3c, R3d, R4

- F2. **查看图鉴（Compendium）**
  - **Trigger:** 儿童在 Portal 页面点击星星旁边的图鉴图标
  - **Actors:** A1, A2
  - **Steps:**
    1. Portal 页面展示图鉴图标（书本/收集册样式），旁边显示已搜集总数
    2. 点击图标打开图鉴浮层，按场景分组展示已搜集的物件
    3. 每个物件以 SVG 图标展示，下方标注对应英文单词
    4. 未搜集的物件显示为灰色剪影 + 问号
  - **Outcome:** 儿童看到自己的搜集进度，被激励继续探索未搜集的词汇
  - **Covered by:** R4, R5

- F3. **图鉴中学习单词**
  - **Trigger:** 儿童在图鉴浮层中点击某个已搜集的物件
  - **Actors:** A1, A2
  - **Steps:**
    1. 引擎通过 TTS 朗读该单词（发音）
    2. 引擎调用 LLM 为该单词生成一个适合 6-12 岁儿童的简单例句和中文解释
    3. TTS 朗读例句
    4. 例句和解释以文字气泡形式展示在物件旁边
  - **Outcome:** 儿童听到单词发音、看到例句，加深对该词汇的理解
  - **Covered by:** R7, R8, R9

## Requirements

### 场景内搜集交互

- R1. 引擎在每个场景中，根据场景配置的 `targetVocabulary` 自动生成可搜集物件。每个词汇对应一个物件，渲染为小型 3D 标记物（如悬浮旋转的卡片/星星），放置在场景地图中可到达的地面位置。
- R2. 当儿童角色进入物件的一定触发范围（默认约 2 米）时，物件发出可见的光效（glow），并在物件旁显示「E」交互提示（桌面端键盘 E 键 + 鼠标可点击）。
- R3. **发现时刻**：儿童按下 E 或点击按钮后，物件 SVG 图标放大浮现到屏幕中央。引擎立即通过 TTS 朗读该单词的发音（清晰、慢速，适合 6-12 岁儿童跟读）。这是教学核心时刻——让孩子先听到并记住单词发音，搜集是其次。
- R3a. 已被搜集过的物件不再发光、不再显示「E」提示、不可再次搜集——同一次会话和跨会话均生效。
- R3b. 搜集物默认无任何文字或图标提示其存在——儿童必须靠走近发现（发光是唯一的可见线索）。
- R3c. **重复发音**：发现时刻界面显示喇叭按钮（🔊），儿童可反复点击多次重听单词 TTS 发音，无限次。学习优先于搜集——不听完不确认也可以。
- R3d. **确认搜集**：儿童点击确认按钮（如「Got it! ✓」或点击 SVG 本身）后，引擎播放庆祝动画（SVG 缩小淡出 + 喝彩/清脆铃铛音效），持久化到数据库，物件从场景消失（或显示为灰色已搜集状态）。确认前不写入数据库——儿童若关闭页面，该词汇下次仍可被发现。

### 跨会话持久化

- R4. 搜集记录持久化到服务端数据库（SQLite `progress.db` 或新增表），字段至少包含：`word`（词汇）、`scene_id`（所属场景）、`collected_at`（搜集时间戳）。
- R4a. 引擎在场景加载时从服务端查询当前儿童已搜集的词汇列表，用于判断哪些物件应隐藏/不可交互。
- R4b. 持久化在搜集成功时即时写入（非会话结束时批量写入），避免浏览器刷新导致搜集丢失。

### Portal 图鉴入口

- R5. 在 Portal 页面的星星计数（`#star-count`）旁边新增图鉴图标按钮，图标样式为书本/收集册。图标旁显示已搜集物件总数（如 `📖 12`）。
- R6. Portal 加载时从服务端 API 获取已搜集物件总数和分场景统计，用于渲染图标计数。

### 图鉴浮层

- R7. 点击图鉴图标打开全屏或大型浮层，按场景分组展示所有搜集物。每个场景区域标题为该场景名称和搜集进度（如「🍽️ Restaurant 3/7」）。
- R7a. 已搜集的物件显示为彩色 SVG 图标 + 对应英文单词。未搜集的物件显示为灰色剪影 + 问号。
- R7b. 浮层支持关闭（点击遮罩或关闭按钮），回到 Portal 主页面。

### 词汇学习交互

- R8. 在图鉴浮层中点击任意已搜集的物件，引擎通过 TTS 朗读该单词的发音。
- R9. 引擎调用 LLM（DeepSeek V4 Flash）为该词汇生成一个适合 6-12 岁儿童的简单英文例句和简短中文解释。TTS 朗读例句。例句和解释以文字气泡形式展示。
- R9a. 例句为一次性生成后随响应返回——不做持久缓存以避免过期问题，但同一会话内点击同一单词不重复请求 LLM（内存缓存）。

## Acceptance Examples

- AE1. **Covers R1, R2, R3, R3c, R3d, R4.** 给定餐厅场景 `targetVocabulary: ['hamburger', 'pizza', 'salad']`，引擎自动在场景地面放置 3 个搜集物。8 岁儿童走到一个发光物件旁，看到「E」提示，按下 E 键——`hamburger` 的 SVG 图标浮现在屏幕中央，TTS 朗读「hamburger」。儿童点击喇叭按钮听了 3 遍跟读，然后点击「Got it! ✓」确认——庆祝动画播放、音效响起、物件消失、数据库写入。刷新页面后重新进入餐厅，该物件不再发光。如果儿童按下 E 后没有点击确认就关闭了页面，下次进入餐厅该物件仍然发光可发现。
- AE2. **Covers R5, R6, R7.** Portal 页面加载后，星星旁显示图鉴图标 `📖 5`。点击打开浮层，看到「🍽️ Restaurant 3/7」——3 个彩色 SVG + 单词，4 个灰色剪影 + 问号。点击遮罩关闭浮层。
- AE3. **Covers R8, R9.** 在图鉴浮层中点击已搜集的 `hamburger`，TTS 朗读「hamburger」。LLM 生成例句「I like to eat a hamburger with fries.」和中文解释「汉堡包，一种夹着肉饼的面包」，TTS 朗读例句，文字气泡显示在物件旁。

## Success Criteria

- 一个 8 岁儿童在完成餐厅对话任务后，愿意继续在场景中走动探索、主动搜集至少 1 个物件，而非直接离开场景。
- 儿童在下一次打开 Portal 时，能看到上次搜集的物件的数量变化，并被激励进入场景搜集更多。
- 场景作者只需定义 `targetVocabulary`，无需额外配置，即可使所有目标词汇自动成为可搜集物件——零额外成本。

---

## Scope Boundaries

### Deferred for later

- 搜集物之间的稀有度分级（普通/稀有/传说）
- 搜集进度奖励（如集齐某场景全部物件解锁特殊道具/皮肤）
- 跨场景的全局搜集成就系统
- 搜集物在场景内的随机动态放置算法（V1 使用固定位置或简单规则放置）
- 搜集音效的精细化设计（不同场景/不同稀有度不同音效）
- 图鉴内的搜索和筛选功能

### Outside this product's identity

- **完整的游戏成就系统**——不做类似 Xbox/PlayStation 的成就徽章和 Gamerscore，只做轻量的搜集进度展示。
- **社交分享/排行榜**——搜集数据不对外公开，不做好友间的搜集竞赛。
- **NFT/区块链化的数字藏品**——搜集物是纯粹的教学工具，不与任何链上资产挂钩。

## Key Decisions

- **混合架构（方案 C）**：引擎内置常用少儿英语词汇 SVG 映射库，`targetVocabulary` 中的词汇自动成为搜集物并匹配内置 SVG。场景可通过显式 `collectibles` 字段覆盖位置、SVG 或补充映射库外的词汇。选择依据：兼顾零配置起步（AI 生成场景）和精细化控制（手工场景），初始架设成本与纯内置方案几乎相同。
- **搜集系统完全平行于对话任务**：搜集不阻塞对话、对话不解锁搜集。两个系统独立运行，儿童在场景中的任何时刻都可以自由探索和搜集。
- **搜集物默认无文字提示**：物件不显示单词名称、不在地图上标记位置。发光是唯一的可见线索。设计意图：保持发现的惊喜感，避免让搜集变成按图索骥的任务清单。

---

## Dependencies / Assumptions

- **依赖：SVG 映射库**。引擎需要维护一个常用少儿英语词汇 → SVG 图标的映射表，初期覆盖 New Concept English / 常见 CEFR A1-A2 词汇（预估 200-300 词）。未被映射的词汇需要有兜底展示策略（如首字母图标）。
- **依赖：SQLite**。利用已有 `better-sqlite3` 的 `progress.db`，新增 `collectibles` 表。无需引入新的数据库依赖。
- **依赖：TTS (Kitten TTS)**。单词发音和图鉴例句朗读均复用现有 TTS 管线，不引入新的 TTS 服务。
- **依赖：LLM (DeepSeek V4 Flash)**。例句生成复用现有 LLM 管线（已用于意图路由），新增一个轻量的例句生成 prompt。LLM 不可用时降级为只读发音、不显示例句。
- **依赖：音频素材**。搜集成功音效需要一个或多个音频文件（wav/mp3），需要寻找或制作适合儿童的庆祝音效。
- **假设：单人单机**。当前没有用户系统，所有 Portal 访问者共享同一个数据库——搜集数据不做用户隔离。这是 V1 的已知限制，在引入用户系统前成立。
- **假设：桌面端 (Chrome/Edge) 优先**。搜集交互的「E 键」提示假设桌面键盘可用。移动端的替代交互（点击/长按）推迟到移动端适配阶段。

## Outstanding Questions

### Deferred to Planning

- [Affects R1][Technical] 搜集物在场景内的默认放置策略——使用固定位置规则（如沿墙面均匀分布）还是基于种子随机？需要平衡实现复杂度和探索趣味性。
- [Affects R1][Technical] 搜集物的 3D 渲染形态——悬浮卡片、旋转星星、还是其他？需要和现有体素风格的视觉一致性评估。
- [Affects R2][Technical] 发光效果（glow）的实现方式——Three.js 的 emissive 材质、光晕 sprite、还是后处理 bloom？受限于「不做游戏引擎」约束，需要简洁方案。
- [Affects R3][Needs research] 搜集成功音效的来源——自行录制、免版税素材库、还是 AI 音效生成。
- [Affects R3a][Technical] 跨会话持久化的用户标识——V1 无用户系统，是否需要至少引入一个简单的 localStorage 用户 ID 作为隔离键。
- [Affects R9][Technical] LLM 例句生成的 prompt 设计和缓存策略细节。
- [Affects R7][Technical] 图鉴浮层的 CSS 布局和动画交互设计——需要和现有的 Portal 视觉风格一致。
